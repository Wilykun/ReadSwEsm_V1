1. *ANTITAG — Proteksi Mention Massal*
   ~Member biasa dapat men-tag hampir semua anggota grup tanpa tindakan dari bot.~
   • Mention native `@semua` dan mention yang mencakup minimal 90% anggota terdeteksi sebagai tag massal.
   • Pesan member biasa dihapus tanpa balasan; owner dan admin grup tetap dikecualikan.
   • Bot harus menjadi admin agar dapat menghapus pesan.
> _Hasil: tag massal dihapus tanpa memenuhi grup dengan balasan bot._

🐛 *BUG FIX*
━━━━━━━━━━━━━━━━━━━━━━
1. *ANTITAG — Deteksi Peran Pengirim Lebih Akurat*
   ~Pencocokan hanya memakai `id/jid`, sehingga identitas PN dan LID tertentu tidak cocok dengan metadata peserta.~
   • Pencocokan kini memeriksa `id`, `jid`, `phoneNumber`, dan `lid`.
   • Jika pengirim tidak bisa dipastikan dari metadata, bot melewati penghapusan agar admin tidak salah terkena.
> _Hasil: bot lebih akurat membedakan admin grup dan member biasa._
2. *ANTITAG — Payload Native `@semua` Terlewat*
   ~Handler hanya mencari `mentionedJid` dan melewati pesan `groupMentionedMessage` Baileys.~
   • Payload wrapper dan `groupMentions` sekarang dibaca sebelum pesan dinyatakan tidak relevan.
   • Log error dan hasil penghapusan menyertakan ID pesan.
> _Hasil: pesan native `@semua` masuk ke jalur deteksi dan aksi hapus._

🚀 *PERUBAHAN*

1. *ANTITAG — Format Pesan Lebih Rapi*
   ~Balasan memakai bingkai bergaris yang membuat teks terasa penuh.~
   • Bingkai dekoratif diganti dengan format tebal, miring, dan kutipan sesuai konteks.
   • Syarat dan pengecualian memakai daftar poin; langkah aktivasi memakai nomor.
   • Perintah seperti `.antitag on` dan `.antitag off` ditampilkan dengan format kode.
> _Hasil: pesan Anti-Tag lebih mudah dibaca dan petunjuk perintah lebih jelas._
2. *ENV — Backup Konfigurasi Bot via GitHub*
   ~`push.sh` otomatis mengeluarkan `.env` dari index sehingga konfigurasi bot tidak ikut ter-backup.~
   • Root `.env` tidak lagi diabaikan oleh `.gitignore`.
   • `push.sh` kini mempertahankan `.env` saat menyiapkan file untuk upload.
> _Hasil: konfigurasi bot dapat ikut ter-backup bersama source code._
3. *ANTITAG — Mode Debug Console*
   • `.antitag debug on/off/status` mengatur log ID, tipe pesan, peran pengirim, dan alasan aksi.
   • Log dibatasi ke payload `@semua`, mention massal yang terdeteksi, dan tag bot—bukan pesan grup biasa.
> _Hasil: pesan yang lolos atau dihapus dapat ditelusuri dari ID di console._

🐛 *BUG FIX*

1. *PUSH.SH — Upload Gagal Saat Memisahkan Commit Runtime*
   ~File runtime yang dipilih untuk upload bisa gagal di-stage ulang karena folder `data/` diabaikan oleh `.gitignore`.~
   • Restaging memakai force hanya pada path runtime yang sudah masuk pilihan upload.
   • `.env` dan `.token.secret` tetap dikecualikan dari restaging agar tidak ikut ter-upload.
   • Detail error Git sekarang ditampilkan jika staging runtime masih gagal.
> _Hasil: commit kode dan data runtime dapat dipisah tanpa membocorkan file rahasia._
2. *PUSH.SH — Pilihan Force Push Menjalankan Force Push Sungguhan*
   ~Pilihan `f` hanya menjadi konfirmasi; script masih mencoba push biasa dan graft histori remote.~
   • Force push langsung memakai `--force-with-lease` terhadap SHA remote yang terlihat saat konfirmasi.
   • Jika GitHub menolak, script menampilkan alasan dan tidak membuat graft atau fallback force tersembunyi.
> _Hasil: pilihan `f` menimpa branch remote sesuai konfirmasi, atau berhenti dengan error yang jelas._
